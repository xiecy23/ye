# 私教 · 零基础固定器械训练助手

一个纯静态网页应用，针对**零基础新手**解决四个具体问题：

| 问题 | 在哪解决 |
|---|---|
| 不认识器材 | 「器材」页 —— 描述外观反查 / 按部位找区域 / 拍照存证 |
| 不知道怎么定目标 | 「目标」页 —— 1 分钟问卷，输出 8 周可衡量目标 |
| 不知道练什么 | 「计划」页 —— 目标自动映射到部位和动作 |
| 没有合理计划 | 「计划」页 —— 部位轮转 + 48 小时间隔 + 渐进规则 |

**所有数据只存在手机浏览器本地，不上传任何服务器。**

## 一、怎么用（手机上）

### 部署到 GitHub Pages

1. 新建一个 GitHub 仓库（公开仓库即可，Pages 免费）
2. 把 `fit-coach` 目录里的**全部文件**推到仓库根目录
   ```powershell
   cd C:\新建文件夹\dpsk\fit-coach
   git init
   git add .
   git commit -m "init: 零基础固定器械训练助手"
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```
3. 仓库 → **Settings → Pages → Source 选 `main` 分支 / `root`**
4. 等 1 分钟，得到 `https://<你的用户名>.github.io/<仓库名>/`

### 装到手机主屏

1. 手机浏览器打开上面那个网址
2. **iPhone**：Safari → 分享 → 「添加到主屏幕」
   **Android**： Chrome → 右上角菜单 → 「安装应用」/「添加到主屏幕」
3. 从主屏图标打开，就是一个独立 App，**断网也能用**

> ⚠️ 首次必须联网一次（Service Worker 要下载缓存）。之后完全离线。

### 本地先看一眼

```powershell
cd C:\新建文件夹\dpsk\fit-coach
python -m http.server 8931
# 浏览器打开 http://127.0.0.1:8931/
```

## 二、这个项目为谁做了什么取舍

**学员画像**（决定了下面所有设计）：左高右低的高低肩，左侧上斜方肌长期紧张极易代偿；曾因单臂高位下拉 20kg 导致左斜方肌严重代偿酸痛；腿部训练后重度延迟性酸痛；臀部极易抽筋。目标是改善健康和体态，不追重量。

### 红线不是提示，是代码

这是整个项目的地基。红线做成**三道闸**，任何一道不过，计划就出不来：

| 闸 | 位置 | 作用 |
|---|---|---|
| 打标记 | `safety.js` → `markAll()` | 每个动作在数据加载时就被判定是否禁用 |
| 过滤 | `safety.js` → `filter()` | 禁用动作在**生成阶段**就被剔除，不是生成完再隐藏 |
| 强校验 | `safety.js` → `assertSafe()` | 计划生成完再校验一遍，违规直接拒绝输出 |

红线内容：

1. **禁止自由重量** —— 杠铃、哑铃、Smith 机、深蹲架
2. **禁止单臂拉/推** —— 必须双手对称
3. **禁止肩峰撞击类** —— 肩推机、直立划船、过头推压、上斜方肌训练
4. **禁止大重量** —— 默认上限 25kg；**高位下拉永久 5kg**（因单臂 20kg 伤史，不随进度上调）
5. **上斜方肌风险动作直接禁** —— `trapRisk: high` 一律不用

界面层**不允许**绕过：你在界面上点不出一个禁用动作，因为它压根不在计划里。

### 识别器材靠"姿态 + 动作"，不是靠长得像

纯静态网页没有视觉模型，所以 `recognize.js` 走两条路：

- **描述反查**：你说「躺着推的」，靠姿态判别（躺/坐/站/趴）+ 动作判别（推/拉/夹/弯/伸/外展/内收）定位，比单纯比对字面相似度准得多。实测 26 条口语描述，Top-1 命中 **85%**
- **拍照存证**：照片压缩后存本地，点一下导出清单发给我，我读图后回你精确答案，并写回器材库

剩下的 15% 不是 bug，是**真实歧义**——比如「躺着推的」，水平推胸、低位推胸、平板卧推本来都躺着推。所以界面会给 Top-3 候选，每台都带外观描述，你自己认一下。

## 三、目录结构

```
fit-coach/
├── index.html              单页应用（四个 tab）
├── manifest.webmanifest    PWA 清单
├── sw.js                   Service Worker（离线缓存）
├── icon.svg                图标
└── app/
    ├── id-alias.js         器械 id 归一化（解决两套命名的对不上问题）
    ├── safety.js           ★ 红线引擎，三道闸
    ├── data-machines.js    44 台器材（21 可用 / 7 注意 / 16 禁用）
    ├── data-exercises.js   57 个动作（40 可用 / 17 禁用）
    ├── goal.js             目标引导 + 8 周三阶段
    ├── plan.js             部位轮转 + 渐进规则 + 反馈响应
    ├── recognize.js        器材识别（中文模糊匹配 + 拍照）
    ├── log.js              训练日志（localStorage）
    ├── api.js              可选的开源数据增强（永远降级）
    ├── app.js              界面逻辑（不做任何安全判断）
    └── app.css             样式（手机优先）
```

## 四、改配置改哪里

| 想改什么 | 改哪里 |
|---|---|
| 重量上限 / 伤史 / 训练频率 | `app/safety.js` 的 `SAFETY_PROFILE` |
| 加器材 | `app/data-machines.js`（照抄现有格式） |
| 加动作 | `app/data-exercises.js`（`category` 不含 `free_weight`/`unilateral`/`overhead_press` 才可用） |
| 改目标问卷 | `app/goal.js` 的 `PAINS` |
| 改周计划轮转 | `app/plan.js` 的 `TEMPLATES` |
| 改反馈话术 | `app/plan.js` 的 `REACTIONS` |

## 六、已知限制

1. **离线加载依赖 Service Worker**。若被浏览器清理，会显示引导页而不是白屏（已加兜底）。
2. **识别引擎不是视觉模型**。多台机器外形相似时会给多个候选，需要你点一下确认。这比猜错强。
3. **开源动作库接入是可选的**，默认不联网。点「拉取」才会请求 free-exercise-db，失败自动降级，不影响任何功能。
4. **进阶后要手动解锁**。8 周结束时如果所有动作都做干净了，可以调高 `SAFETY_PROFILE` 里的上限——但**高位下拉的 5kg 建议永久不动**。
